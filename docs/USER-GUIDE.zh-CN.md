# Smooth Motion 使用手册

## 第一次开始
1. 打开游戏，使用窗口或无边框模式，先确认游戏自身运行正常。
2. 在左侧选择配置。首次使用推荐默认配置：2×、WGC、垂直同步、显示队列 3。
3. 保留“倒计时后使用前台窗口”，回到游戏后按 Ctrl + Alt + S；或者明确选择游戏窗口，再点击“开始插帧”并在倒计时内切回游戏。
4. 等待引擎准备完成。首次运行需要创建 GPU 管线，之后可复用程序自己的缓存。若看到“模型已就绪，请切回游戏”，只需回到游戏；控制界面不再因等待前台超过 30 秒就报初始化失败，等待期间可停止。
5. 再按 Ctrl + Alt + S 停止。Ctrl + Alt + Esc 为紧急停止。
6. 游戏原生帧率和最终展示帧率不同：游戏自己的计数通常不包含外部插帧结果，请结合叠层监测观察。

## 游戏配置
左侧的加号新建配置，铅笔编辑，垃圾桶删除选中配置。默认配置保留，不能删除。
配置可按程序名、完整路径或窗口标题匹配；多个条件用英文分号分隔，支持 * 和 ? 通配符。
“自动选择”只在你主动开始插帧时匹配配置，不会自行捕获其他窗口。
开始前保存更改。正在运行时，影响引擎的选项要先停止，再修改并重新开始；HUD 开关可以实时生效。
所有配置位于程序目录 UserData/settings.json，保存有备份。旧 R988 配置迁移后取消旧的短测试自动停止时间。

## 帧生成倍率
2× 是推荐模式：每两个相邻输入之间生成 1 张中间帧，保留已有 FP16 / Intel XMX 优化路径。
4× 和 8× 是实验性递归模式：分别实际计算 3 张和 7 张中间帧。先生成中点，再用中点和原始帧生成更细的时刻；每张结果拥有不同内容时间戳，按时间顺序展示，不靠重复展示凑数。
这些高倍率不是原模型原生支持任意时刻，也不是 LSFG 的同一算法。它们会增加推理工作、功耗、延迟和累积伪影，不能认为从 2× 调到 8× 就会免费得到四倍流畅度。
高倍率选项只有在对应实现通过检查后才开放；当前界面未开放的选项不会被暗中替换成 2×。
显示器刷新率和 GPU 吞吐还会限制实际能看到的帧数。30 FPS × 8 代表理论 240 FPS 内容序列，不代表 120 Hz 屏幕能展示全部 240 张。
基础帧不稳定或 GPU 已经满载时，先使用 2×；优先让游戏基础帧有余量。

## 捕获 API
WGC（Windows Graphics Capture）：按目标窗口捕获，是默认路径。它有窗口级捕获语义，但窗口最小化、失焦、显示模式变化仍可能触发暂停或重建。
DXGI（Desktop Duplication）：实验性桌面复制路径，裁出游戏客户区。它捕获的是显示器桌面，不能保证被其他窗口遮挡的游戏内容仍然完整。需要游戏在前台且完整处于同一显示器；窗口移到其他显示器、访问丢失或条件不满足时会明确停止或暂停。
DXGI 不是“必然更快”的选项。Windows 版本、MPO、VRR、驱动、光标和合成路径都会影响结果。比较时保持游戏场景、尺寸和设置相同，分别记录捕获延迟、最终展示和画面正确性。
不会静默把失败的 DXGI 测试当成 WGC 成绩。测试新路径时先短测，确认没有捕获叠层自身或遮挡内容。
本产品不提供 GDI 路径，也没有宣称已经实现其所有私有捕获技术。

DXGI 实验捕获暂不合成光标，选择它时会关闭捕获光标。WGC 可单独选择是否捕获光标。

## 输出方式、切换窗口与退出游戏
“处理尺寸”决定插帧处理的图像尺寸，“渲染选项 → 输出方式”决定它最终显示在哪里，二者独立。
- 跟随游戏窗口：保留现有叠层，覆盖游戏客户区并使用原位置键鼠操作。游戏无边框全屏时，叠层也跟随该区域。
- 无边框全屏 · 预览：输出填充游戏所在显示器，保留画面比例并补不透明黑边，不修改全局显示模式。
- 1080p 窗口 · 预览：输出窗口客户区不超过 1920×1080，桌面工作区放不下时缩小。
- 等于处理尺寸 · 预览：输出窗口按实际处理像素尺寸建立，工作区放不下时缩小。
- 小窗口 · 预览：不超过 960×540，适合查看结果。
独立输出预览仅支持 WGC，选择时切换为 WGC；改选 DXGI 捕获会回到跟随游戏，避免捕获预览自身。
独立预览保持游戏前台接收键盘、手柄及游戏自身的相对输入，但没有跨位置的绝对鼠标菜单映射。它不是完整的鼠标游戏全屏替代模式。
点击预览会请求停止插帧并隐藏输出，Win32 窗口点击被消费；这不承诺能拦截游戏自行读取的 Raw Input。Ctrl+Alt+Esc 始终可紧急停止。需要鼠标菜单操作时先退出预览。
“游戏全屏状态”仍仅描述游戏窗口几何；预览窗口的输出尺寸和实际画面尺寸单独显示，不混淆输入、处理和输出。
失焦、最小化、隐藏或关闭游戏沿原保护暂停/停止，不抢焦点。已提交的 GPU 工作仍需安全收尾。
不修改全局分辨率、刷新率、VRR、电源计划、驱动、游戏限帧或游戏自身画质。

## 渲染与延迟
同步模式：垂直同步使用 DXGI 的同步展示；立即提交取消该同步间隔，但不保证桌面合成器允许撕裂，也不保证延迟一定更低。
显示队列：控制交换链的最大帧延迟，当前可选 2、3、4。更小的值减少排队空间，也可能更容易受 GPU 抢占影响；更大可能改善连续性，但增加排队延迟。
时间线缓冲：给捕获、推理和展示留出固定时间，推荐 80 ms。增大到 100、120、160 或 200 ms 会增加操作延迟，不能将其称为推理提速。
不透明内容合成：沿用现有实验优化，可能改善桌面合成节奏，也可能影响少数边缘像素；出现异常时可以关闭对照。
游戏窗口叠层：输出覆盖游戏客户区，键盘和鼠标应继续传给游戏。游戏失焦或最小化时安全暂停；不会修改全局分辨率、刷新率、VRR、驱动或电源计划。
这些设置与游戏内垂直同步、限帧是不同控制。程序不会擅自更改游戏配置。

## 分辨率与屏幕比例
捕获尺寸取自目标窗口的实际客户区物理像素。游戏内的渲染分辨率与这个尺寸可能不同：例如游戏内部以 1920×1080 渲染，再提交 2880×1620 的窗口画面，WGC 得到的仍是后者。
“捕获 → 处理尺寸”可选原生、1080p 上限（1920×1080）、1440p 上限（2560×1440）。上限模式按比例缩小，不拉伸，不放大小窗口；超宽、竖屏和奇数尺寸按比例取整。插帧后通过显示合成放回游戏客户区。
例：2880×1620 捕获 → 1920×1080 处理 → 2880×1620 显示。2880×1800 在1080p上限下为1728×1080，保持16:10画面比例。界面分列捕获、处理、显示尺寸。
缩放可能损失文字与细线细节。模型架构和权重不变，内部768×432多尺度网格保持；不能将其称为原生捕获尺寸的性能达标。WGC帧池仍按源尺寸工作，新增采样本身也有开销。
小窗口可使用独立全屏预览；绝对鼠标菜单映射尚未提供。跟随游戏模式保留原位置输入。
1080p 是此前主要验证目标，不是模型只能支持的唯一尺寸。奇数尺寸、超宽或竖屏不能仅因宽高比不同就被拒绝。
实际可用尺寸仍受显卡纹理限制、计算派发限制以及当前内存预算约束。程序在分配资源前进行检查，失败时显示具体资源原因；不会把内存不够伪装成模型固定分辨率；只有明确选择处理上限才会缩小输入。
模型内部原有的多尺度计算仍保留。更大输出会增加捕获、纹理、中间资源和合成成本；不保证 4K 与 1080p 同样快。
运行中改变游戏客户区尺寸可能需要重新准备资源；出现暂停时先停止，再在新尺寸下启动。

## 长时间游玩
日常运行默认持续开启，直到你主动停止、退出游戏或发生需要停止的错误，不再因为 15 分钟的测试时限自动结束。
原先“会话”指一次从开始到停止的运行记录，不是限制玩家游玩时间。运行记录用于定位错误。
设置中的“诊断时限”只用于可重复短测试，可设为不限制或明确时长。日常使用保持不限制。
停止、设备异常保护和进程心跳仍然有效；取消自动计时不等于关闭保护。
日志会受容量限制或轮转，避免持续数小时无限占用磁盘；诊断记录截断会明确标记。
“能够持续运行”与“已通过连续 2–4 小时游戏稳定性验收”是两件事。长测结论应查看当前版本验证记录，不依据开关作保证。

## 监测面板怎么看
Ctrl + Alt + F8 显示或隐藏面板，Ctrl + Alt + F9 切换详细指标。
展示 FPS 来自 Windows / DXGI 展示观测。原生和生成分开显示；Present 提交成功不等于实际上屏，更不等于光学测量。
显示 ≥ 时表示观测不完整，只能提供下限；横线表示数据不可用，不能当作零。1% low 需要足够有效样本。
GPU 驱动域功耗是驱动报告的域；封装功耗是处理器封装口径，两者分别标注，可能覆盖重叠资源，不能直接相加。
它们都不是插帧独占增量，也不是整机墙上功耗。要计算插帧增量，需要相同场景、相同基础帧的开关对照并注明测量误差。
详细指标包括提交、超期、模型时间等。判断流畅度还应看帧间隔波动、基础帧、延迟和实际画面，不能只看一个 60 FPS 数字。

## 常见问题
点击开始却没有捕获：先确认倒计时结束时游戏仍在前台，没有最小化；也可从窗口列表明确选择并刷新。
快捷键无效：在设置里换用其他组合；系统或其他软件已占用时界面会提示，不要连续反复按键。
DXGI 黑屏或画面不对：停止，确认窗口没有跨屏或被遮挡，再切回 WGC；不要反复启动绕过错误。
开插帧后游戏更慢：通常说明共享 GPU 或功耗预算紧张。先用 2×，查看原生帧是否下降；更高倍率会进一步增加成本。
出现白点、黑条、持续花屏、设备错误或明显卡死：立即停止，保留记录；不要通过修改驱动恢复设置来绕过。
发生故障锁定：打开运行记录查看错误，点击“确认后恢复”只解除锁定，不会立刻启动 GPU；再主动开始。
界面显示的是提交数而游戏看起来不流畅：检查实际展示覆盖率、超期和帧间隔，不将提交数当作显示帧数。
最小化或关闭主窗口：是否进入托盘由设置决定。退出应结束本程序拥有的引擎；不要同时运行两个插帧版本。

## 数据与回退
这是便携程序。配置、缓存、日志都保存在程序目录 UserData，不需要安装开发环境，不修改系统 PATH、注册表或安全设置。
“打开运行记录”可以找到每次启动配置、错误和帧数据。分享记录前请先检查其中可能包含的窗口标题和路径。
原版目录保留。回退时先停止并退出新版本，确认插帧引擎已结束，再打开旧版本；不要同时启动以免抢占 GPU。
手册描述实现和使用方式；具体通过了哪些画质、性能、分辨率和长时间测试，以随包验证记录为准。




## 故障诊断（记录格式 994，客户端 R995）
运行时默认持续记录。安全停止后，在“设置 → 本地数据 → 导出诊断包”保存可分析的本地 ZIP。详见 [诊断手册](DIAGNOSTICS.zh-CN.md)。诊断不自动上传，不采集画面或键鼠输入。版本符号与源码随维护证据包保存。
