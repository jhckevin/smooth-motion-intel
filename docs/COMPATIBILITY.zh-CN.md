# 设备兼容与验证边界

推荐 Intel Arc B390 / Panther Lake。其他 Intel XMX 显卡（包括 B580/B570）不再按产品名或设备 ID 拒绝，但尚无这些设备的实测结果。XMX 或 XeSS 支持不是完整的 Vulkan/互操作能力证明。

## 选择与拒绝

R995 按真实能力选择 Intel Vulkan 设备，再以 LUID 绑定 D3D11 适配器；不允许跨卡把资源或传感器误配。队列按实际 flags/数量选择，不假定计算队列固定为第 1 族、WSI transfer 固定为第 2 族。默认不要求高全局队列优先级。

完整最低要求和每个拒绝原因由原生能力探测代码及报告记录，见 native/adapter_policy995.h 和 native/device_probe995.h。当前模型使用 FP16 8×16×16 cooperative matrix，同时还依赖其 shader 声明的子组、浮点控制、存储/算术类型和共享资源能力。模型 SPIR-V 中的 scalar FP8 转换不能因主要矩阵计算是 FP16 就省略。

没有相关 float8 扩展的 GPU/驱动需要新的兼容 shader 包；当前发行版没有伪造该功能或自动降级到不等价实现。能力通过也不等于真实推理、游戏画质和持续运行通过。

## 只读能力报告

在独立可写目录调用同版本引擎：

~~~powershell
.\SmoothMotion-Engine.exe --device-capabilities995
~~~

输出 app-capabilities995.jsonl。该路径只枚举设备和查询能力，不导入模型、不创建捕获窗口、不提交推理或渲染工作。退出码 0 表示找到合格设备，3 表示不可用/不支持，2 表示报告文件失败；同时应读取每张卡的能力和拒绝原因，不能把退出 0 当成推理成功。

运行时的 D3D/Vulkan 设备身份、队列和传感器归属还会进入诊断记录。不能取得传感器或确认同卡对应时，功耗显示为不可用，不能把另一张卡的功耗当成绩。

## 当前验证

- 项目已有 B390 的历史开发/游戏测试；新版本设备选择有独立 CPU 策略测试和只读探测。
- CPU 测试的 B390/B580 是合成能力记录，验证策略不会错误地按产品 ID 封锁，不能据此宣称 B580 实机支持。
- 公开构建与 CI 不带模型，也不执行 GPU 推理。
- 新显卡报告应同时提供：程序版本、驱动、能力报告、捕获/处理/输出尺寸、捕获与展示路径、诊断包；性能结论还需要有效展示、延迟、画质和持续运行证据。

不要为绕过拒绝修改驱动安全设置或删除能力检查。与模型资产有关的权利边界见 MODEL-ASSETS.zh-CN.md。
